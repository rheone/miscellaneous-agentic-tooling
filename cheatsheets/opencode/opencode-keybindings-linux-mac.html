OpenCode Keybinding Cheat Sheet

Default keybinds · Linux / macOS edition
Leader: Ctrl+X  then  key

1Leader Key Basics

Ctrl+X→keyLeader combo (2s window, configurable via leader_timeout in tui.json)
Ctrl+POpen command palette
You don't have to put custom keybinds behind the leader, but it's strongly recommended to avoid conflicts with your terminal or shell. The leader timeout defaults to 2000 ms.

4Subagent / Session Navigation

Ctrl+X ↓Go to first child session
→Cycle to next child session
←Cycle to previous child session
↑Go to parent session
The arrow keys (→, ←, ↑) intentionally skip the leader key for quick subagent navigation, making them more prone to terminal conflicts than leader-prefixed shortcuts. To move them behind the leader, remap in tui.json, e.g. "session_parent": "<leader>up".

15Platform Notes: Linux vs macOS

  • Terminal suspend (both): Ctrl+Z suspends OpenCode to the background by default. Run fg in your shell to resume it. Because Ctrl+Z is reserved for suspend, it is not part of Undo here (unlike Windows) — use Ctrl+- or Cmd+Z/Super+Z instead.
  • macOS: Super maps to Cmd. Many Alt-based shortcuts (Alt+F, Alt+B, Alt+D, the Ctrl+Alt which-key shortcuts) need Option acting as Meta:
    • iTerm2: Settings → Profiles → Keys → General → set Option key to "Esc+"
    • Terminal.app: Settings → Profiles → Keyboard → check "Use Option as Meta Key"
    • VS Code: set "terminal.integrated.macOptionIsMeta": true
    Paste is Cmd+V.
  • Linux: Alt-based shortcuts work natively — no Meta configuration needed. Super is your Windows/Super key; desktop environments like GNOME or KDE often intercept it for the Activities/app overview, which can swallow Super+Z/Super+A before OpenCode sees them. Remap in tui.json or disable the conflicting OS shortcut if this happens. Paste is typically Ctrl+V.
  • Shift+Enter works natively in most Linux/macOS terminal emulators. If yours doesn't send it, use Ctrl+Enter, Alt+Enter, or Ctrl+J instead.

16Customizing Keybinds

Edit tui.json in your OpenCode config directory (typically ~/.config/opencode/tui.json). Example:

{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
    "leader": "ctrl+x",
    "session_new": "<leader>n"
  }
}
  • Multiple bindings: separate with commas, e.g. "ctrl+g,home"
  • Leader prefix: use <leader>, e.g. "<leader>n"
  • Disable a keybind: set its value to "none"

17VS Code Integrated Terminal

VS Code's integrated terminal intercepts some keystrokes before they reach OpenCode. The most commonly affected default bindings are:

Ctrl+FVS Code terminal find (conflicts with model favorite toggle)
Alt+← / Alt+→VS Code navigate back/forward (conflicts with word backward/forward)
Ctrl+GVS Code terminal find (conflicts with jump to first message)
Ctrl+KVS Code chord prefix / clear (conflicts with delete to end of line)

Workarounds (pick one):

  1. Use the leader key — Most affected bindings have a leader-prefixed equivalent (e.g. Ctrl+X M instead of Ctrl+A for model list). Prefer these in VS Code's terminal.
  2. Override VS Code shortcuts — Forward keys to the terminal by adding to VS Code's keybindings.json: 
    {
  "key": "ctrl+f",
  "command": "-workbench.action.terminal.focusFind",
  "when": "terminalFocus"
},
{
  "key": "alt+left",
  "command": "-workbench.action.navigateBack",
  "when": "terminalFocus"
},
{
  "key": "alt+right",
  "command": "-workbench.action.navigateForward",
  "when": "terminalFocus"
},
{
  "key": "ctrl+g",
  "command": "-workbench.action.terminal.focusFind",
  "when": "terminalFocus"
}
  3. Remap in tui.json — Move conflict-prone direct keys behind the leader: 
    {
  "keybinds": {
    "model_favorite_toggle": "<leader>f",
    "input_word_forward": "<leader>w",
    "input_word_backward": "<leader>b"
  }
}

To debug what VS Code is doing with a keypress, run Developer: Toggle Keyboard Shortcuts Troubleshooting from the VS Code command palette.
